# 点击器 — 开发规格说明（供 AI / 工程实现）

本文是实现规格。按文中已锁定的决策编码，不要再把「范围外」做成功能，不要为兼容旧系统改架构。

## 0. 已锁定的产品约束

1. Android 应用，只跑在一台 Android 16 设备上。`minSdk = targetSdk = compileSdk = 36`。不为旧版本写分支。
2. 用户可添加任务。任务正文是一条可编排脚本：步骤可任意插入、复制、调序，动作只有三种：打开应用、等待、点击屏幕上的某个位置。执行时严格按编排顺序自上而下跑完。
3. 任务可以设置一个运行时刻，到点执行一次。没有周期、没有 cron、没有重复间隔。
4. 无 root、无 adb、无网络、无账号、无云同步。
5. 语言：Kotlin。界面：单 Activity + Jetpack Compose。本地库：Room。

## 1. 目标与使用方式

个人在自己的手机上预先编排一段操作，到指定时刻自动做完：打开某个已安装应用，等待若干毫秒，再在固定坐标点一下。可重复添加多条任务，每条任务各自只自动跑一次。

典型例子：明天 08:00 打开「时钟」应用，等待 800ms，点击 (540, 1600)。

手动「立即执行」与到点执行走同一套执行器。编辑器里允许单步试运行，用来核对坐标。

## 2. 本期范围

| 能力 | 行为 |
| --- | --- |
| 任务列表 | 展示名称、状态、计划时间、最近一次结果摘要 |
| 新建 / 编辑 | 名称、可选的计划时间、脚本编排 |
| 步骤编排 | 竖向脚本。动作只有 `打开应用`、`等待`、`点击`。可在任意位置插入、删除、复制、上移、下移、拖拽排序 |
| 取点 | 在目标界面上点一次，把该点的绝对坐标写入当前点击步骤 |
| 立即执行 | 忽略计划时间，马上跑整条任务 |
| 单步试运行 | 只执行编辑器里选中的那一步 |
| 到点执行 | 计划时间到达后执行一次 |
| 取消 | 执行中可从通知取消；未执行的计划任务可取消闹钟 |
| 结果 | 成功、失败、错过、已取消，并保留一句原因 |

### 本期范围外

- 条件分支、循环、并行、步骤间跳转。编排是一条直线
- 周期任务、法定工作日、隔 N 天
- 滑动、长按、多指、输入文字、按键、返回键
- 图像识别、找控件 id、按文本点击
- 录制用户真实操作再回放
- 输入 PIN、图案、密码，或绕过安全锁屏。无密码时的点亮屏幕和划掉滑动锁屏在范围内
- 多设备、第二块屏幕、外接显示器
- 桌面小组件、快捷设置磁贴
- 导入导出、备份

## 3. 架构

```text
ui（Compose）
  TaskListScreen / TaskEditScreen / PermissionGate
        │
        ▼
domain
  Task, Step, TaskRepository, ExecutionSnapshot
        │
        ├─ schedule：AlarmScheduler + BootReceiver
        └─ exec：ClickerRuntimeService + ClickerAccessibilityService + ExecutionEngine
                │
                ▼
data：Room（Task, Step）
```

模块职责：

| 模块 | 职责 |
| --- | --- |
| `ui` | 编辑与展示。执行过程中不把本应用界面盖在目标应用上 |
| `domain` | 任务与步骤的不变量。不含 Android 框架类型 |
| `data` | Room 持久化。进程被杀死后，计划任务和步骤仍在 |
| `schedule` | 把「状态 = 已计划」的任务注册成一次性闹钟；开机后按库内记录重注册 |
| `exec` | 真正打开应用、等待、点击。只接受一份不可变快照，执行中不读界面草稿 |

依赖方向：`ui → domain ← data`，`schedule` 与 `exec` 依赖 `domain`。`exec` 不直接改 UI 状态，只写仓库并更新前台通知。

建议包名：`com.local.clicker`。

```text
app/src/main/java/com/local/clicker/
  ui/
  domain/
  data/
  schedule/
  exec/
```

### 3.1 执行链路

到点：

1. `AlarmManager.setAlarmClock` 触发 `AlarmReceiver`。
2. `AlarmReceiver` 只做两件事：校验任务 id，然后 `startForegroundService`。广播内不跑步骤。
3. `ClickerRuntimeService` 进入前台（通知常驻），取出快照，交给 `ExecutionEngine`。
4. 引擎通过无障碍服务执行步骤。
5. 写回终态，撤掉前台通知，`stopSelf`。

立即执行与单步试运行也进入同一个 `ClickerRuntimeService`，避免第二条执行路径。

### 3.2 为什么用这些系统能力

| 需求 | 选用 | 原因 |
| --- | --- | --- |
| 到点一定触发 | `AlarmManager.setAlarmClock` + `RTC_WAKEUP` | 本应用的价值就是准点执行。该 API 在 Doze 下仍会触发，并在状态栏显示闹钟图标。可以接受 |
| 打开其他应用 | 已启用的 `AccessibilityService` 调用 `startActivity` | 系统允许已启用的无障碍服务从后台拉起界面。普通后台服务做不到 |
| 点击 | `AccessibilityService.dispatchGesture` | 不需要 root。配置里声明 `canPerformGestures=true` |
| 取点浮层 | 无障碍服务的 `TYPE_ACCESSIBILITY_OVERLAY` | 能盖在其他应用上，又不需要单独的悬浮窗权限 |
| 执行期间保活 | 前台服务，`foregroundServiceType=specialUse` | 步骤里的等待可能持续数分钟 |

闹钟请求码使用任务 id 的 int 值（id 由 Room 自增，本应用任务量远小于 2^31）。同一任务重新计划时，用同一 requestCode 覆盖旧闹钟。

## 4. 数据模型

时间一律存 UTC epoch millis。界面用设备本地时区显示。

### 4.1 Task

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id | Long | 自增主键 |
| name | String | trim 后 1～40 个字符 |
| scheduledAt | Long? | 空表示只允许手动执行。非空则必须是保存时刻之后的未来时间 |
| status | enum | 见 4.3 |
| createdAt / updatedAt | Long | |
| lastRunAt | Long? | 最近一次开始执行的时刻 |
| lastMessage | String? | 给人看的一句结果，最长 200 字 |

### 4.2 Step

脚本是 `List<Step>`，界面从上到下就是执行顺序。每张卡片一种动作，用密封类型表达，禁止用可空字段拼出「三种都像又都不全」的行。

```kotlin
sealed interface Step {
    val id: Long
    val orderIndex: Int
}

data class OpenAppStep(override val id: Long, override val orderIndex: Int, val packageName: String) : Step
data class WaitStep(override val id: Long, override val orderIndex: Int, val waitMs: Long) : Step
data class TapStep(
    override val id: Long,
    override val orderIndex: Int,
    val x: Int,
    val y: Int,
    val screenWidth: Int,
    val screenHeight: Int,
    val rotation: Int,
) : Step
```

Room 用单表 + `type` 判别列保存。读出后立刻映射成上面的密封类型；与当前 `type` 无关的列不得进入领域对象。

| 类型 | 完成条件 |
| --- | --- |
| `OpenAppStep` | `packageName` 非空，且当前设备存在带 `ACTION_MAIN` + `CATEGORY_LAUNCHER` 的 Activity |
| `WaitStep` | `waitMs` 为整数，闭区间 `[100, 120_000]` |
| `TapStep` | 已取点。`x ∈ [0, screenWidth)`，`y ∈ [0, screenHeight)`。`rotation` 为取点时的 `Display.rotation` |

`orderIndex` 从 0 连续。每次编排操作结束后立刻重排，保存到库里的也是重排后的结果。

步骤数闭区间 `[0, 30]`，含未完成卡片。0 步或任一卡片未完成时，脚本不可执行。

点击坐标是默认屏幕的绝对像素，原点在屏幕左上角，包含状态栏区域。与 `dispatchGesture` 的坐标系一致。

### 4.2.1 编排操作

编排只发生在编辑页的内存草稿上。`RUNNING` 时不提供这些操作。领域层提供纯函数，界面只调用它们，不在 Composable 里手改下标。

| 操作 | 结果 |
| --- | --- |
| 追加 | 用户先选动作类型，在末尾加一张该类型的未完成卡片 |
| 插入 | 插到某一张的上方或下方，同样先选类型。新卡片未完成 |
| 删除 | 去掉该卡片，其后卡片前移。允许删到 0 张 |
| 上移 / 下移 | 与相邻卡片交换。第一张不能上移，最后一张不能下移 |
| 拖拽 | 放到新下标，其余卡片顺延。放下位置与原位置相同则无变化 |
| 复制 | 深拷贝插到原卡片正后方。点击步骤连同坐标和屏幕参数一起复制。未完成卡片也允许复制 |
| 更换类型 | 位置不变，换成另一种动作的未完成卡片。原类型字段丢弃 |

新卡片的 `id` 用尚未入库的临时负数，保存时由 Room 分配正式 id。移动、复制以外的字段修改不改变 `id`。复制生成新的临时 id。

未完成卡片留在草稿里，用明确状态表示，而不是塞一个非法的 `waitMs` 或空坐标进密封类型。编辑草稿用：

```kotlin
sealed interface DraftStep {
    val key: Long
    val orderIndex: Int
}
data class DraftOpenApp(..., val packageName: String?) : DraftStep
data class DraftWait(..., val waitMs: Long?) : DraftStep
data class DraftTap(..., val tap: TapPoint?) : DraftStep
```

`key` 在一次编辑会话内稳定，供 Compose 列表做 key。保存时整份草稿按当前顺序写回步骤表。已完成卡片映射成 `Step`；未完成卡片仍落库，但不进入执行快照。持久化规则见 4.2.2。

### 4.2.2 脚本是否可执行

| 草稿内容 | 保存结果 |
| --- | --- |
| 有未完成卡片，或 0 张卡片 | 任务保持 `DRAFT`。不注册闹钟。`scheduledAt` 若填写了未来时间，只记在任务上，供用户补完步骤后再计划 |
| 1～30 张且全部完成，`scheduledAt` 为空 | `DRAFT`。可立即执行，到点不跑 |
| 1～30 张且全部完成，`scheduledAt` 为未来 | `SCHEDULED`，注册闹钟 |
| 步骤数超过 30 | 拒绝这次追加、插入或复制，草稿保持操作前的内容 |

半成品步骤也要落库，否则进程被杀后编排丢失。用同一张步骤表，增加 `complete` 标记：未完成行的类型专属列为空。仓库读出编辑页时得到 `DraftStep`；只有 `complete = true` 且通过完成条件的行才进入执行快照。存在未完成行的任务，执行入口不可用。

从 `SCHEDULED` 再编辑，若保存时脚本变得不可执行：取消闹钟，状态回到 `DRAFT`。

### 4.3 状态

`DRAFT` 草稿：未设置计划时间，或脚本里有 0 步 / 未完成步骤。不会注册闹钟。

`SCHEDULED` 已计划：脚本可执行（1～30 步且全部完成），且 `scheduledAt` 在未来。已注册闹钟。

`RUNNING` 执行中：全局同时最多一条。

`SUCCESS` 成功：全部步骤走完。终态。

`FAILED` 失败：前置条件不满足，或某一步失败。终态，并停止后续步骤。

`MISSED` 错过：到点时没有在宽限内真正开始。终态。不补跑。

`CANCELLED` 已取消：用户在执行中取消，或用户取消了尚未开始的计划。终态。

终态任务保留在列表里，允许「复制为新任务」。复制出来的是 `DRAFT`，步骤深拷贝，`scheduledAt` 清空。终态任务本身不可再改步骤。

从 `SCHEDULED` 进入编辑并保存：先取消旧闹钟，再按新内容决定 `DRAFT` 或 `SCHEDULED`。

### 4.4 快照

开始执行时把任务和已完成步骤按 `orderIndex` 复制成内存快照。执行循环只读这份顺序。之后用户即使改到了数据库（正常流程下执行中禁止编辑），也不影响本次。快照里不包含未完成卡片。

## 5. 调度

### 5.1 注册

保存后若状态应为 `SCHEDULED`，立刻 `setAlarmClock`。`AlarmClockInfo` 的展示 Intent 指向该任务的编辑页。

触发时 Intent 带 `taskId` 与 `scheduledAt`。接收端核对：库里该任务仍是 `SCHEDULED`，且库里的 `scheduledAt` 与 Intent 里的值相同。核对失败则丢弃这次触发，防止旧闹钟或重复投递把已改期的任务再跑一遍。

### 5.2 宽限

计划时刻与「真正开始执行」的差值 ≤ 30 秒：照常执行。

差值 > 30 秒：记为 `MISSED`，原因「已超过计划时间 30 秒，未执行」。不打开应用，不点击。

30 秒覆盖闹钟略晚和前台服务拉起的正常延迟。再晚就可能已经离开用户预设的界面，点击会落在错误的页面上。

### 5.3 排队

执行器是单线程队列，同时只跑一条。

一条正在跑时，另一条闹钟到达：

- 先做 5.2 的宽限判断。已经超时则直接 `MISSED`，不入队。
- 未超时则入内存队列，等待当前任务结束。
- 轮到它真正开始时再查一次宽限。此时若已超过 30 秒，记 `MISSED`，不执行。

队列只活在 `ClickerRuntimeService` 进程内。服务被杀死后不恢复队列。开机只重注册「仍为 `SCHEDULED` 且 `scheduledAt` 在未来」的任务。

### 5.4 开机与进程重启

`BOOT_COMPLETED`：对每条 `SCHEDULED` 且 `scheduledAt` 仍在未来的任务重新 `setAlarmClock`。`scheduledAt` 已过去的改为 `MISSED`。

应用冷启动时做一次同样的对账，补上「闹钟权限刚刚被授予」或「进程死亡导致闹钟丢失」的情况。

冷启动时若发现 `RUNNING`：改为 `FAILED`，原因「执行被中断」。不从中间步骤续跑。

### 5.5 用户改时间与取消

- 把计划时间改到过去：拒绝保存，保留原值。
- 清空计划时间：取消闹钟，状态改为 `DRAFT`（步骤仍合法时也是草稿，因为没有到点任务）。
- 删除任务：取消闹钟，删除步骤行。`RUNNING` 时删除按钮不可用；用户应先取消执行。
- 取消尚未开始的计划：取消闹钟，状态改为 `CANCELLED`。

## 6. 执行器

### 6.1 开始前检查（按顺序，失败即终态）

本机约定不设置 PIN、图案或密码。到点时屏幕通常是灭的，执行器自己把屏幕点亮；若当时只是滑动锁屏，把锁屏划掉。用户不必事先亮屏，也不必事先解锁。

全部通过才把状态写成 `RUNNING`。任一失败则写 `FAILED` 与对应原因，不执行任何步骤。失败退出时撤掉点亮用的浮层。

| 顺序 | 条件 | 失败原因 |
| --- | --- | --- |
| 1 | 无障碍服务已连接 | 无障碍服务未开启 |
| 2 | 快照步骤数在 `[1, 30]`，且每一步都是已完成的密封类型 | 任务步骤不合法 |
| 3 | 每一个 `OPEN_APP` 的包仍有启动 Activity | 应用不存在：{packageName} |
| 4 | `KeyguardManager.isKeyguardSecure == false` | 设备设有锁屏密码 |
| 5 | 3 秒内屏幕已点亮，且 `isKeyguardLocked == false` | 无法点亮或解除锁屏 |
| 6 | 默认显示器的宽、高、rotation 与快照里每一个 `TAP` 步骤记录的一致 | 屏幕分辨率或方向已变化 |

第 4 步用 `isKeyguardSecure`，它只在 PIN、图案、密码时为真。安全设置为「无」或「滑动」时为假。为真则直接失败，不收集密码，不在锁屏上点击。

第 6 步在屏幕已经点亮之后做，拿来和取点时的屏幕逐项比较。有一个点击步骤对不上就整单失败。

### 6.1.1 点亮并保持到脚本结束

由无障碍服务完成，顺序固定：

1. 加上一块 1×1、完全透明、不可点击、不可聚焦的 `TYPE_ACCESSIBILITY_OVERLAY`，带 `FLAG_KEEP_SCREEN_ON`。这块浮层从点亮开始一直留到本次执行结束，避免等待步骤超过系统熄屏时间后屏幕又灭掉。它不接收触摸，点击仍然落在目标应用上。
2. 启动 `WakeActivity`（透明、不进最近任务、`exported=false`）。`onCreate` 里调用 `setTurnScreenOn(true)` 和 `setShowWhenLocked(true)`。
3. `isKeyguardLocked == true` 且 `isKeyguardSecure == false` 时，调用 `KeyguardManager.requestDismissKeyguard`。滑动锁屏会在这里被系统划掉。已经是「无」锁屏时，点亮后锁屏本身不存在，这一步跳过。
4. 等到 `PowerManager.isInteractive == true` 且 `isKeyguardLocked == false`，最多 3 秒。
5. `finish()` 掉 `WakeActivity`，并确认它已不在前台，然后再跑第一步。点亮用的界面不能盖住目标应用。

不用手势去猜锁屏滑条的位置。解除锁屏只走 `requestDismissKeyguard`。

执行中每一步开始前再查一次：屏幕仍点亮且 `isKeyguardLocked == false`。否则当前步失败，原因「屏幕已熄灭或已锁定」，后续步骤不跑。

脚本结束、失败或用户停止时，在 `finally` 里移除这块浮层，屏幕恢复系统自己的熄屏策略。

### 6.2 步骤语义

**打开应用**

- 用 `PackageManager.getLaunchIntentForPackage`。
- Intent 增加 `FLAG_ACTIVITY_NEW_TASK`。
- 由无障碍服务 `startActivity`。
- 启动抛异常，或 3 秒内前台应用包名仍不是目标包：该步失败，原因「打开应用失败：{packageName}」。
- 成功后不额外等待。用户若需要界面稳定，自己在后面加等待步骤。

**等待**

- `delay(waitMs)`，可被取消打断。
- 被取消时不再执行后续步骤。

**点击**

- 一次 `dispatchGesture`：在 `(x, y)` 按下，50ms 后抬起，单指，`willContinue=false`。
- 手势回调失败：该步失败，原因「点击失败：({x},{y})」。
- 回调成功即视为该步成功。不检查点击后界面是否变化。

### 6.3 失败与取消

- 任一步失败：立即停止后续步骤，任务 `FAILED`，`lastMessage` 写明第几步（从 1 计）和原因。
- 用户从通知点「停止」：置取消标志，当前等待立刻结束，当前手势不再继续后续步骤，任务 `CANCELLED`。
- 整次执行墙钟超过 10 分钟：停止，`FAILED`，原因「执行超过 10 分钟」。
- 成功：`SUCCESS`，`lastMessage` 为「已完成 N 步」。

### 6.4 执行中的界面

- 前台通知标题：正在执行「{任务名}」。
- 内容：步骤 i/N，以及这一步的短标签（打开 xxx / 等待 xxx ms / 点击 x,y）。
- 通知动作：停止。
- 不启动本应用的 Activity，不抢占目标应用的前台。
- 结束后发一条普通通知：成功、失败、错过或已取消，带 `lastMessage`。点通知打开该任务详情。

### 6.5 单步试运行

复用引擎，但快照里只有选中的一步，且不修改任务的计划状态。

- 试运行使用一条独立的内存任务，不写入 `RUNNING` 到原任务上。原任务若是 `SCHEDULED`，闹钟保持不变。
- 试运行与整单执行共用同一队列。有任务正在执行时，试运行按钮不可用。
- 点击步骤仍做分辨率与方向检查。
- 结果用 Toast 或编辑页横幅展示，不把原任务打成 `SUCCESS` / `FAILED`。

## 7. 取点

入口在点击步骤上：「选取坐标」。

1. 无障碍未连接时，按钮进入权限引导，不开始取点。
2. 无障碍已连接：显示说明「请先手动打开要点的界面，再点悬浮按钮」。同时在屏幕边缘放一个约 48dp 的悬浮按钮（`TYPE_ACCESSIBILITY_OVERLAY`）。
3. 用户自己切到目标应用。
4. 用户点悬浮按钮。按钮消失，换成全屏半透明层。
5. 用户在半透明层上点一下。这一下被浮层消费，不传给下层应用。
6. 记录该点的绝对坐标，以及当时的 `width`、`height`、`rotation`，填回当前步骤。
7. 关掉浮层，回到编辑页。编辑页显示 `x, y` 与 `宽×高 / rotation`。

点返回或浮层上的「取消」：丢弃本次取点，步骤原坐标保持不变。

取点过程中若无障碍断开：关闭浮层，提示重新开启。

## 8. 界面行为

### 8.1 列表

- 按 `scheduledAt` 升序；没有计划时间的排在后面；同组内按 `updatedAt` 降序。
- 每行：名称、状态、计划时间（没有则显示「仅手动」）、`lastMessage`。
- 操作：新建、点进编辑、对 `SCHEDULED` 或 `DRAFT` 立即执行。终态行提供「复制为新任务」。

### 8.2 编辑与编排

编辑页上半部分是名称和计划时间（日期 + 时间，本地时区，精确到分钟；存盘时秒和毫秒归零）。下半部分是脚本时间线，这是本页的主体。

时间线：

- 竖向卡片，顺序即执行顺序。左侧标 1…N。
- 每张卡片默认收成一行摘要：`打开 时钟`、`等待 800ms`、`点击 (540, 1600)`。未完成时摘要为 `打开应用（未选择）`、`等待（未填写）`、`点击（未取点）`。
- 点卡片展开，编辑该动作的字段。同一时刻只展开一张。
- 卡片菜单：上移、下移、复制、删除、在下方插入。第一张不显示上移，最后一张不显示下移。
- 卡片可拖拽排序。拖拽时显示插入位置。也保留上移 / 下移，避免只靠拖拽。
- 底部「添加步骤」：先弹出三个动作，选中后追加到末尾并展开新卡片。
- 已有 30 张时，添加、插入、复制不可用，并提示已达上限。
- 打开应用：从本机可启动应用里选，展示应用名，保存包名。列表使用 `MAIN`/`LAUNCHER` 查询。
- 等待：数字输入，范围外在字段下写明允许区间，该卡片保持未完成。
- 点击：只通过取点写入坐标，不提供手输。未取点则卡片未完成。
- 更换类型时先确认，确认后该位置变成一张未完成的新类型卡片。

`RUNNING` 时整页只读，不显示编排操作。

保存写回编排草稿。脚本不可执行时留在编辑页，并标出未完成卡片，不注册闹钟。脚本可执行且保存成功后回到列表。

### 8.3 权限引导（进入主界面前必须可完成）

按此顺序检查，缺哪个展示哪个的开启入口：

1. 通知权限（`POST_NOTIFICATIONS`）。
2. 无障碍服务。Android 13 起旁加载应用要先在应用信息里允许「受限制的设置」，然后才能在无障碍里打开本服务。引导文案写清这两步。
3. 精确闹钟权限（设置里的「闹钟和提醒」）。未授予时可以编辑和立即执行，不能把任务保存为 `SCHEDULED`。
4. 开机自启动以接收 `BOOT_COMPLETED`。在本机系统设置里允许本应用开机启动。引导只提供跳转说明和检测：下次冷启动对账时，若存在本应重注册却没有闹钟的 `SCHEDULED` 任务，列表顶部提示「计划可能在重启后丢失，请检查自启动」。

电池优化白名单不作为功能开关。若本机仍出现准时性问题，引导页放一句说明：在系统设置里对本应用关闭电池限制。

无障碍服务的声明文案写明：本服务用于在你设定的时刻打开应用并点击你事先选好的坐标，不会读取通知、不会上传屏幕内容。

## 9. 权限与清单

| 权限 / 组件 | 用途 |
| --- | --- |
| `POST_NOTIFICATIONS` | 执行中通知、结果通知 |
| `SCHEDULE_EXACT_ALARM` | `setAlarmClock` 在目标版本上仍需用户授予「闹钟和提醒」 |
| `RECEIVE_BOOT_COMPLETED` | 重启后重注册闹钟 |
| `FOREGROUND_SERVICE` | 执行期前台服务 |
| `FOREGROUND_SERVICE_SPECIAL_USE` | 配套 `foregroundServiceType=specialUse`，并在 manifest 里用 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` 写明「按用户计划执行一次屏幕操作」 |
| `QUERY_ALL_PACKAGES` | 应用选择器需要列出全部可启动应用。本应用无上架需求，直接声明该权限 |
| AccessibilityService | `canPerformGestures=true`。只声明完成打开应用、点击、取点浮层所需的能力 |
| `BootReceiver` | `BOOT_COMPLETED`，`exported=false`（由 manifest intent-filter 接收系统广播时按系统要求设置 exported；若必须 exported，则不暴露其他 action） |
| `AlarmReceiver` | `exported=false`，仅本应用 PendingIntent 可发 |
| `WakeActivity` | 透明、`excludeFromRecents`、`exported=false`。只负责点亮屏幕并请求系统划掉非安全锁屏，脚本开始前必须已 `finish` |

不申请：悬浮窗、使用情况访问、录音、相机、存储、网络。

## 10. 边界条件汇总

| 场景 | 行为 |
| --- | --- |
| 计划时间不是未来 | 拒绝保存 |
| 计划时间与现在相差不到 1 分钟 | 允许。宽限仍是开始执行时相对 `scheduledAt` 的 30 秒 |
| 0 步、存在未完成卡片、等待超出范围、点击未取点、包名不可启动 | 可以保存为草稿。状态保持 `DRAFT`，不注册闹钟，不能立即执行 |
| 已有 30 步时再追加、插入或复制 | 拒绝该操作，草稿不变 |
| 调序、插入、删除 | 只改脚本顺序。不改变其他卡片里已经填好的应用、等待和坐标 |
| 复制点击步骤 | 新步骤使用同一套坐标和取点时的屏幕参数 |
| 更换步骤类型 | 该位置变为未完成卡片，原字段丢弃 |
| 两个任务时间相同 | 都注册闹钟。真正开始时按到达顺序排队，各自单独计算 30 秒宽限 |
| 闹钟重复投递、或投递的是改期前的旧时间 | 核对 `taskId + scheduledAt + status`，不一致则丢弃 |
| 执行中修改或删除 | 界面禁止。服务侧若收到执行请求时状态已不是 `SCHEDULED` 且也不是「立即执行」入口，则不跑 |
| 执行中关机或划掉进程 | 下次冷启动把 `RUNNING` 记为 `FAILED` / 执行被中断 |
| 重启后计划时间还在未来 | 重新注册闹钟 |
| 重启后计划时间已过 | `MISSED` |
| 到点时屏幕是灭的，且没有 PIN / 图案 / 密码 | 先点亮屏幕。若是滑动锁屏则由系统划掉，然后再执行步骤 |
| 到点时已设置 PIN / 图案 / 密码 | `FAILED`，原因「设备设有锁屏密码」。不点击，不尝试解锁 |
| 点亮或划掉滑动锁屏超过 3 秒仍未就绪 | `FAILED`，原因「无法点亮或解除锁屏」。不点击 |
| 执行过程中屏幕再次熄灭或锁屏出现 | 当前步失败，后续步骤不跑 |
| 取点后旋转了屏幕，或分辨率不同 | `FAILED`，不点击 |
| 目标应用被卸载 | 开始前失败 |
| 打开应用后前台不是目标包 | 该步失败并停止后续步骤 |
| 点击落在错误页面 | 仍视为点击成功。正确页面由用户用「打开应用 + 等待」自己保证 |
| 单步等待 100ms～120s，整单墙钟超过 10 分钟 | 整单失败 |
| 无障碍在执行中途被关掉 | 当前步失败，任务 `FAILED`，原因「无障碍服务已断开」 |
| 立即执行一个已过点的终态任务 | 不允许。须先复制为新任务 |
| 立即执行 | 仅当脚本可执行（1～30 步且全部完成）且状态为 `DRAFT` 或 `SCHEDULED`。`SCHEDULED` 被立即执行后取消闹钟；成功、失败、取消都进入对应终态，到点不再跑 |
| 试运行 | 不改变原任务状态和闹钟 |

立即执行会消耗这条「一次」语义：一个已计划任务若被提前手动跑了，到点不再自动跑。

## 12. 实现顺序

按这个顺序做，每步都可在设备上单独验证：

1. 工程骨架：Compose、Room、第 4 节的表、列表，以及脚本编排（追加、插入、删除、复制、上下移、拖拽）。此步用手动输入坐标代替取点，不做闹钟和真实点击。
2. 无障碍服务骨架与权限引导。
3. 执行引擎的三步语义 + 立即执行 + 前台通知 + 停止。
4. 取点浮层，把坐标写回点击步骤。编辑页去掉手输坐标，只保留取点结果。
5. `setAlarmClock`、触发核对、30 秒宽限、开机重注册、冷启动对账。
6. 单步试运行、复制为新任务、终态只读。

## 13. 验收

在这台 Android 16 设备上人工确认：

1. 新建任务并编排成：打开一个已安装应用，等待 1 秒，点击取到的坐标。再插入一步、把某步移到末尾、复制一个点击步、删掉复制出来的那步。保存后顺序与界面一致。立即执行后，点击落在取点位置。
2. 脚本里留一张未取点的点击卡片时可以保存草稿，不能立即执行，也不会注册闹钟。补完取点并设好未来时间后，才变为已计划。
3. 计划时间设为约 1 分钟后，到点只执行一次。执行完状态为成功，不再次执行。
4. 把计划时间改到更晚，旧时刻不会触发。
5. 执行过程中点通知「停止」，后续步骤不执行，状态为已取消。
6. 息屏且未设置锁屏密码时到点：屏幕会亮起，然后步骤照常执行。若系统是滑动锁屏，锁屏会被划掉，点击不会落在锁屏上。
7. 把锁屏改成 PIN 后再到点：状态为失败，锁屏上没有发生点击。测完把 PIN 去掉。
8. 取点后旋转屏幕再执行，状态为失败，没有点击。
9. 卸载目标应用后执行「打开应用」，任务失败。
10. 重启设备后，未来的计划任务仍会在新时刻执行；已经过点的任务变为错过。
11. 无障碍关闭时，不能取点，也不能执行。
12. 两条任务计划在同一分钟，两条都会进入终态，且不会并行点击。
